title: Marketplace
description: Публикация, установка и управление плагинами, скилами и MCP-серверами OpenCode.
---

Marketplace устанавливает связанные плагины, скилы, MCP-серверы, команды, агентов и инструкции как один управляемый
пакет. В десктопном приложении откройте **Настройки → Marketplace**, а в TUI запустите **Marketplace** из палитры
команд.

Установленный пакет может оставаться установленным, когда он выключен. Каждый объявленный скил и MCP-сервер также
можно включать или выключать независимо.

Источники Marketplace, установленные пакеты и состояния компонентов хранятся в локальном реестре приложения
OpenCode, а не в `opencode.json` или `opencode.jsonc`. Активные install plans проецируются в эффективную конфигурацию
только в памяти. Поэтому установка, обновление, выключение и удаление пакета не изменяют пользовательский файл
конфигурации.

Команда `opencode plugin marketplace export --name team` экспортирует установленный набор как переносимый профиль.
Заголовки запросов источников, installation receipts и другое локальное служебное состояние в экспорт не попадают.

---

## Добавление каталога

Откройте вкладку **Источники** в десктопном приложении. В TUI откройте **Marketplace sources** или нажмите `Ctrl+S`
в Marketplace.

Источник также можно добавить, не открывая TUI:

```bash
opencode plugin marketplace add https://git.example.com/ai/agent-marketplace.git
```

Источником может быть:

- HTTPS URL JSON-файла Marketplace;
- URL репозитория GitHub;
- сокращение `github:owner/repository`;
- loopback HTTP URL для локальной разработки.

Для URL Git-репозитория с окончанием `.git` OpenCode ищет `.opencode/marketplace.json` через стандартные маршруты
сырых файлов GitHub, GitLab и Gitea. Параметр `--name` задаёт отображаемое имя, а `--trust private` — приватный
каталог.

OpenCode сохраняет квитанции установки, даже если источник выключен, недоступен или удалил элемент. Поэтому
установленным пакетом по-прежнему можно безопасно управлять или удалить его.

Каталоги имеют метки `official`, `verified`, `community` или `private`. Статусы official и verified зарезервированы
для каталогов, распространяемых OpenCode; добавленные пользователем каталоги могут быть community или private.
Метка не изолирует устанавливаемый код. Заголовки приватных источников хранятся только в локальном реестре, скрываются из ответов API и экспортируемых
профилей и никогда не записываются в конфигурацию проекта.

## Формат каталога

Каталог использует схему `opencode.marketplace/v1`:

```json title=".opencode/marketplace.json"
{
  "schema": "opencode.marketplace/v1",
  "id": "acme",
  "name": "Acme Marketplace",
  "items": [
    {
      "id": "review-suite",
      "name": "Review Suite",
      "description": "Проверка изменений с помощью готовых сценариев и инструментов документации.",
      "kind": "plugin",
      "version": "1.0.0",
      "publisher": {
        "name": "Acme"
      },
      "icon": {
        "src-light": "./assets/review-suite-light.png",
        "src-dark": "./assets/review-suite-dark.png"
      },
      "brand_color": "#10A37F",
      "install": {
        "plugins": ["@acme/opencode-review@1.0.0"],
        "skills": {
          "items": [
            {
              "id": "review",
              "name": "review",
              "description": "Проверить текущие изменения.",
              "path": "./skills/review"
            },
            {
              "id": "release-notes",
              "name": "release-notes",
              "description": "Подготовить примечания к выпуску.",
              "path": "./skills/release-notes"
            }
          ]
        },
        "mcp": {
          "docs": {
            "type": "remote",
            "url": "https://docs.example.com/mcp"
          }
        }
      }
    }
  ]
}
```

Используйте стабильные идентификаторы без двоеточий для каталога, каждого элемента и каждого скила.

### Иконки плагинов

У каждого элемента может быть собственная произвольная картинка. Для одной картинки используйте короткую форму:

```json
{
  "icon": "./assets/review-suite.png"
}
```

Чтобы задать разные изображения для тем, используйте `src-light` и необязательный `src-dark`:

```json
{
  "icon": {
    "src-light": "./assets/review-suite-light.png",
    "src-dark": "./assets/review-suite-dark.png"
  }
}
```

Иконкой может быть путь с `./` относительно файла каталога, абсолютный HTTP или HTTPS URL либо data URL с PNG,
JPEG, WebP или GIF в base64. Относительный путь не может выходить за каталог. Если картинка отсутствует или не
загрузилась, десктопное приложение показывает цветную заглушку с инициалами. `brand_color` задаёт её фон
шестизначным HEX-цветом.

### Отдельно управляемые скилы

Объявляйте скилы в `install.skills.items`, чтобы GUI и TUI показывали именной переключатель для каждого из них.
Элементу нужны `id` и настоящее имя скила `name`; также можно указать отдельный `path` или `url`. Несколько скилов
могут использовать один источник. Выключенный именной скил фильтруется и при runtime-обнаружении.

Старые массивы `install.skills.paths` и `install.skills.urls` продолжают поддерживаться. Каждый источник без
метаданных отображается как один переключатель с именем, полученным из пути или URL.

### Другие поля плана установки

План установки также может задавать:

- `plugins`: строки пакетов или кортежи `[package, options]`, поддерживаемые полем конфигурации `plugin`;
- `agents`: конфигурацию именованных агентов и субагентов;
- `commands`: именованные slash-команды;
- `mcp`: конфигурацию локальных и удалённых MCP-серверов;
- `instructions`: пути или URL постоянных инструкций.

Перед заменой существующего плагина, агента, команды или MCP-сервера OpenCode показывает конфликтующие пути и
запрашивает подтверждение.

## Включение и выключение компонентов

В панели сведений десктопного приложения есть переключатели всего плагина, каждого объявленного скила и каждого
MCP-сервера.

В TUI:

- нажмите `Enter` на установленном элементе, чтобы открыть его компоненты;
- нажмите `Space` в списке Marketplace, чтобы включить или выключить весь плагин;
- нажмите `Enter` на компоненте, чтобы переключить его;
- нажмите `Ctrl+D` в списке компонентов, чтобы удалить пакет.

Выключение всего плагина удаляет его активную конфигурацию, но сохраняет квитанцию установки и индивидуальные
настройки. При включении восстанавливаются плагин и все скилы, которые не были выключены отдельно.

Включённые MCP-серверы запускаются автоматически при включении плагина. Если MCP-сервер был явно выключен, выбор
запоминается: выключение и повторное включение всего плагина не запустит этот сервер. После включения собственного
переключателя MCP он снова будет запускаться автоматически.

При удалении восстанавливаются прежние значения из квитанции установки. Значения, изменённые пользователем после
установки, сохраняются и не перезаписываются.

## Обновления и недоступные каталоги

Обновления Marketplace используют тот же механизм квитанций, что и установка. По возможности OpenCode сравнивает
семантические версии, а также обнаруживает изменение fingerprint элемента. Каталог не может превратить
**Обновить всё** в неявный downgrade: более низкая семантическая версия не устанавливается.

Установленные элементы остаются видимыми и доступными для удаления, если их источник выключен, удалён, находится
офлайн или больше не публикует элемент. OpenCode восстанавливает запись из локальной квитанции и снимка.

## Безопасность

Marketplace — это механизм обнаружения и конфигурации, а не песочница.

- Плагины выполняют код внутри OpenCode.
- Локальные MCP-серверы выполняют команды на вашем компьютере.
- Удалённые MCP-серверы получают запросы и могут требовать учётные данные.
- Скилы и инструкции влияют на поведение агента.
- Агенты и команды могут изменять конфигурацию модели, инструментов и разрешений.

Перед установкой проверьте издателя, источник, репозиторий, запрошенные возможности и итоговую конфигурацию. Для
исполняемых плагинов предпочитайте доверенные каталоги и фиксируйте версии пакетов, когда важна воспроизводимость.

## Локальный реестр, кэш артефактов и API

Runtime-состояние Marketplace хранится в SQLite-базе OpenCode. Источники, установленные пакеты, переключатели
компонентов, ссылки на артефакты и монотонная ревизия реестра являются состоянием приложения и никогда не записываются
в `opencode.json` или `opencode.jsonc`.

Ответы каталогов, точные манифесты элементов, иконки, удалённые файлы скилов и удалённые инструкции сохраняются в
content-addressed кэше SHA-256 внутри каталога кэша OpenCode. Перед активацией install plan удалённые скилы и
инструкции материализуются в неизменяемое локальное дерево. При обновлении каталога используются условные HTTP-запросы
с ETag или Last-Modified, а при отсутствии сети OpenCode использует последний успешно проверенный ответ из кэша.

Десктопное приложение и TUI работают через отдельный API `/marketplace`. Каждая мутация передаёт увиденную клиентом
ревизию. Устаревший клиент получает конфликт ревизий и не может незаметно перезаписать изменения другого клиента.
Планирование отделено от установки и обновления, поэтому предупреждения о доверии и конфликты конфигурации можно
проверить до активации исполняемого содержимого.

Фича пока находится в разработке. Таблицы Marketplace создаются обычной миграцией схемы базы данных, но импорт
состояния из экспериментальных `registry.json` или из Marketplace-конфигурации промежуточных коммитов намеренно не
выполняется.
